## Нумерация

В графовых алгоритмах и DSU параметр `n` означает число вершин/элементов;
допустимые номера — `0..n-1`. Примеры чтения графа также ожидают номера с нуля.
Если условие задачи использует `1..n`, переводите номера при чтении.

Это соглашение не меняет границы запросов, ранг k-й подстроки и служебные
номера узлов: у них остаются собственные соглашения соответствующей реализации.

Файлы `.cpp` сохраняются самостоятельными, со своими шапками и примерами
`main`/`solve`. Алгоритмы, вспомогательные методы и обёртки не удаляются.

## Типы и представление данных

Обычное ДО принимает начальный `vi` и присваиваемое значение `int`;
агрегат суммы и результат запроса — `ll`, как в TRD.
Конкретное lazy-ДО называется `min_segtree`: начальный массив `vi`,
значения, прибавления, lazy-теги и результат минимума — `ll`.
У неявного точечного ДО счётчики, прибавления и результат — `int`;
суммы должны помещаться в этот тип. У неявного lazy-ДО они остаются `ll`.
У HLD сумма пути возвращается в `ll`, исходные значения остаются `vi`,
а аргумент прибавления `update` — `int`. Общее `lazy_segtree` сохраняет
параметры `Node`/`Lazy`: нужные 64-битные поля задаются при его использовании.

Пулы неявных ДО по умолчанию не резервируют большой массив: нужный резерв
можно передать вторым аргументом конструктора.

Для мостов и точек сочленения `graph[v]` хранит пары `(u,id)`.
Оба направления одного ребра имеют одинаковый уникальный неотрицательный `id`.
Кратные рёбра имеют разные `id`; DFS пропускает только родительское ребро.

## Результаты графовых алгоритмов

- `bridges::solve(graph)` возвращает `vector<pii>` мостов;
  `dots::solve(graph)` — `vector<bool>` флагов точек сочленения.
- В `paths_negative.cpp` трёхаргументный `bellman_ford(s,n,edges)` возвращает
  `BellmanResult {dp,parent,cycle}`; `get_path(target)` восстанавливает путь.
  Старый четырёхаргументный вариант с `target` сохранён как печатный пример.
- `floyd_yorshell(n,matrix)` возвращает `FloydResult {dp,nxt,cycle}`;
  прежняя локальная функция восстановления доступна как `get_path(u,v)`.
  Диагностический вывод сохранён отдельно в `floyd_example`.
- В обоих результатах восстановление консервативно возвращает пустой путь
  при `cycle=true` или недостижимости. Сами расстояния при отрицательных
  циклах не следует считать конечными кратчайшими расстояниями.
- Сводные шаблонные варианты `shortest_path_neg` в `exam_2sem.cpp` уже
  возвращают массивы расстояний; их существующий интерфейс сохранён.
- `centroid_decomp(graph, root=0)` принимает начальную вершину построения;
  `centroid_parent` заполнен, у корня дерева центроидов `-1`.

## LCA

Оба варианта оформлены как в TRD: классы `LCA` и `fast_LCA` хранят таблицы
в объекте, строятся в конструкторе и предоставляют `query(u,v)`:

```cpp
LCA lca(root, graph);          // двоичные подъёмы, запрос O(log n)
fast_LCA fast(root, graph);    // Euler tour + RMQ, запрос O(1)
int ancestor = lca.query(u, v);
```

Размер таблицы подъёмов вычисляется по размеру дерева. Вспомогательные
`dfs` и `get_lca` сохранены как методы. Для другого дерева или корня
создайте новый объект. Вершины — `0..n-1`; построение и запросы требуют непустого дерева.

## Готовая связка HLD и дерева отрезков

В `graphs/heavy_light.cpp` и его сводной копии перед HLD находится конкретный
`HldSegtree` из TRD: прибавление на отрезке и сумма, с `ll` для сумм и тегов.
Исходное универсальное lazy-ДО сохранено отдельно.

```cpp
HLD<HldSegtree> hld(root, graph, values);
hld.update(u, v, delta);     // прибавить int delta каждой вершине пути
ll sum = hld.query(u, v);   // сумма вершин пути, оба конца включены
```

HLD раскладывает путь на O(log n) отрезков массива. `HldSegtree` обрабатывает
каждый отрезок за O(log n), итоговый запрос/обновление — O(log² n).
Поле `tr` обычное; пустой конструктор нужен до присваивания `tr=Segtree(vals)`.
При прибавлении `d` на внутреннем полуинтервале `[l,r)` сумма увеличивается
на `d*(r-l)`, lazy-тег — на `d`. Внешние границы `update/query` включительны.

## Sparse table и топосорт

`SparseTable(a)` строит таблицу минимумов неизменяемого массива;
`query(l,r)` возвращает минимум на включительном `[l,r]`. Пример ввода/вывода
в `main`/`solve` сохранён и использует этот класс.

`topo_sort` возвращает `false` при цикле, ничего не печатает и не завершает
процесс. Подготовьте нулевые `color` и пустой `ans`, вызовите DFS для всех
компонент; при успехе разверните `ans`, при ошибке отбросьте частичный ответ.
Демонстрационный `solve` сохраняет сообщение о цикле.

## Проверка согласованных исправлений

Из корня репозитория, GCC с C++23:

```bash
g++ -std=c++23 -O1 -fsanitize=address,undefined -fno-omit-frame-pointer -Wno-return-type tests/approved_regressions.cpp -o /tmp/sportprog-regressions
ASAN_OPTIONS=detect_leaks=0 UBSAN_OPTIONS=halt_on_error=1 /tmp/sportprog-regressions
```

Тесты используют реальные исходные `.cpp` и проверяют исправления LCIS,
ModInt, модульного Гаусса, неявного lazy-ДО, битового бора, повторного запуска
2-SAT, насыщения Флойда, позиционного treap и переход на нулевую нумерацию,
включая повторные реализации в `exam_2sem.cpp`. Для treap проверяются
`insert`, `erase`, `split`, `merge`, `get_kth` сравнением с обычным вектором.
Дополнительно проверяются 64-битные значения ДО/HLD и мосты/точки сочленения
на случайных несвязных мультиграфах с петлями независимым удалением рёбер/вершин.
Проверяются возвращаемые результаты/пути кратчайших путей и баланс дерева
центроидов, заданного `centroid_parent`.
Оба LCA и их сводные копии проверяются на случайных корнях, нескольких
независимых объектах сравнением с подъёмом по родителям.
Готовый `HLD<HldSegtree>` проверяется на явных путях и поддеревьях; sparse
table — прямым минимумом, топосорт — независимым алгоритмом Кана.
